# GIS Design System

## 1. Brand identity

**Name:** Get Inspired Society

**Tone:** Sober, declarative. No marketing register, no urgency, no pressure on a call to action. No long dashes — use a comma, a full stop, or a line break. Never the word "community" in public copy. Issue titles (e.g. "Bloom", "No Algorithm", "Wonder") are always written in sentence case, never all caps, even for a name that looks like an acronym: this applies to the rendered result too, so an issue title placed inside (or inheriting) a `text-transform:uppercase` rule needs its own `text-transform:none` wrapper, or that element's uppercase styling has to go if the title is the whole of its content.

**Anchor lines:**
- *No algorithm decides what's here.* — Home

**Audiences:** Two audiences — makers and viewers. For their definitions, see `docs/gis-project-brief.md` section 2. They are introduced late on each page and never separated in the navigation.

## 2. Typography

One family: **Archivo variable**, axes `wdth 75..125` and `wght 400..700`. Display sizes use the width axis, not a second typeface. Everything under 20 px stays at normal width.

**Self-hosted, not Google Fonts.** Since the privacy/font-self-hosting task (see CLAUDE.md), Archivo is served from our own domain: `public/assets/fonts/Archivo-Variable.woff2` (the same latin-subset variable file Google Fonts used to serve, same `wdth`/`wght` axes, SIL Open Font License 1.1, `public/assets/fonts/OFL.txt`), preloaded with `<link rel="preload" as="font" type="font/woff2" href="/assets/fonts/Archivo-Variable.woff2" crossorigin>` and declared in an `@font-face` with `font-display: swap` right in each page's own `<style>` block. No page loads anything from `fonts.googleapis.com` or `fonts.gstatic.com` any more, including `/admin` and `/embed`; `test/main-landmark-fonts.test.js` asserts both. The old "preload a stylesheet + `media=\"print\"` swap + `<noscript>` fallback" trick (needed only because that stylesheet lived on Google's domain) is gone: a same-origin `@font-face` with `font-display: swap` is non-blocking on its own, so a plain preload link is enough.

**Metrics-matched fallback.** Every page lists a second font-family, `'Archivo Fallback'`, directly after `'Archivo'` in the stack: an `@font-face` built on `local('Arial')` (then `Helvetica`/`Liberation Sans`/`Helvetica Neue`) with `size-adjust: 99.2%`, `ascent-override: 87.8%`, `descent-override: 21%` and `line-gap-override: 0%`. These four numbers come straight from Archivo's own `hhea` table (ascent 878, descent -210, lineGap 0, unitsPerEm 1000) and from the ratio of its `xAvgCharWidth` to Arial's, not a guess, so the system font that briefly shows before Archivo loads takes the same line height and very nearly the same text width, eliminating the layout shift the swap used to cause (mobile CLS on `/` and `/magazine` dropped from 0.0805 to 0). The width (`wdth`) axis itself is not compensated for on display headings: an attempt to add a matching `font-stretch` percentage next to each heading's `font-variation-settings:'wdth'` value broke the *already-loaded* Archivo's own `ch`-unit sizing on `/submit`, a real, visible regression, so it was removed. See CLAUDE.md for the full account. `/submit`'s own `max-width: 16ch` on its hero statement had that same `ch`-unit problem independently (a pre-existing Chromium quirk where the unit isn't always recomputed when a swapped-in webfont changes the font metrics), and was fixed separately by replacing it with a fixed `max-width: 11.518em`, the same width measured directly in Archivo; `test/submit-wrap-stability.test.js` loads the page ten times and checks the line breaks never change.

## 4. Components

Nine components. Every component is demonstrated live in `docs/design-system.html`.

**Masthead**
Navigation bar. Ink background, white text. On scroll: wordmark drops from 88 to 40 px and the black bar arrives (`400ms`). Bar retreats upward on scroll down, returns on scroll up (`450ms`). Navigation items are Magazine, Gallery and Open call, as outlined pills (`.menuitem`). There is no log-in action, no Society item and, since the On View weekly wall is out of the navigation for the duration of the issues-focused homepage (see §5), no On view item either: Society, Circle and On view were removed from the nav, and `/society` answers a 301 to `/`. `/on-view` and `/work/:slug` still exist and still work (reachable from the issue 05 card's fallback, direct links, search engines, etc.). Only the nav/footer entry point is gone, not the route. **Open call is temporary:** it links to `/submit` (the Wonder open call page) and is only marked current there (`aria-current="page"`); it belongs in the nav and footer only while that call is actually open (now through 6 December 2026, see `CLAUDE.md`'s "Nav-item 'Open call'" entry) and must be removed or swapped for the next call's equivalent once it closes.

Below `860px` (the same breakpoint the tile grid and doors collapse at in the live pages, e.g. `build/pages/index.html`'s `.grid`/`.doors`) the row is replaced by a hamburger toggle to the right of the wordmark. The wordmark drops to a fixed 40 px: it no longer scales with viewport width. The toggle opens a fullscreen ink panel, always white-on-ink regardless of the desktop nav's colour variant (`data-variant="light"` included): Magazine / Gallery are stacked in page-title-weight type (`wdth 116`, `700`). Opening moves focus to the first item; `Esc` or a link click closes it and returns focus to the toggle. The animation collapses under `prefers-reduced-motion: reduce`. The toggle carries `aria-expanded` (toggled true/false), `aria-controls` (pointing at the panel's id) and an `aria-label` that switches between "Open menu" and "Close menu" — verified against Chromium's accessibility tree, not just the DOM attributes. The wordmark stays visible and tappable while the panel is open — it sits above the panel (`z-index:2` against the panel's `1`) rather than being covered by it. This was a deliberate choice over adding a separate "back to home" control inside the panel: the wordmark already is the home link everywhere else in the system, so keeping it live avoids introducing a second, redundant way to do the same thing, and needed only a z-index change rather than new markup.

Shared markup, styles and script live in `build/partials/nav.html` and are injected into every build-system page; `public/on-view/index.html`, `public/work/index.html` and every magazine reader (`public/magazine/<slug>/index.html`, found by glob) carry identical hand-maintained copies since they sit outside the build system (see `docs/gis-project-brief.md`/CLAUDE.md — `/on-view` is deliberately excluded from the build pipeline). `npm run build` runs `build/check-nav-drift.js` first and aborts if that copy has drifted from the partial (markup, toggle script, and the toggle's `aria-expanded`/`aria-controls`/`aria-label` are all compared explicitly — an ARIA-only edit fails the check by name, not just as a generic "markup drifted"); run it standalone with `npm run check:nav-drift`. `npm run test:nav-drift-aria` is the regression test proving that ARIA sensitivity — it temporarily mutates the partial's `aria-label`, asserts the drift check names the mismatch, then restores the original file.

> **Breakpoint note:** the nav's mobile threshold (`860px`) intentionally does not match the `760px` used in `docs/design-system.html`'s own demo-page layout (`.spec`, `.erow`, `.tiles`, `.doors` — the documentation page's grid, not the live site's). `860px` was chosen because it is the value the actual production components collapse at (the nav's own pre-existing tablet tweak, and the homepage's `.grid`/`.doors`). `760px` only exists inside the design-system reference page itself and governs that page's own two-column documentation layout, unrelated to any live component. The two are not harmonized because they solve different problems — one is a live-site component breakpoint, the other is a documentation-page layout breakpoint — and forcing them to match would make one of the two collapse at the wrong width for its own content.

**Button**
Outlined pill in the current text colour, one shape, three grounds (paper / ink / blue). On hover: fills with its opposite and the gap between label and arrow widens. There is no filled primary button anywhere.

**Statement panel**
A blue field with one line and nothing else competing. Exactly one per page. The line rises from below the fold of its own container when it enters view. Never two on a page, never a paragraph next to it.

**Editorial row**
A label on the left, one sentence on the right, an optional link at the end. Used for routing on Contact. Stacks on mobile.

**Archive row**
For lists where every entry is a destination. On hover the entire row fills blue — the same vocabulary as the tile grid, stretched into a line. Cover image lifts and scales on hover.

**Tile**
Images sit at reduced brightness and grayscale until approached; on hover they lift to full brightness. The artist name appears on a gradient, not a card. Tiles never carry buttons — the whole tile is the target.

**Doors**
Two halves of equal weight: one on paper, one on blue. This is the only place where the two audiences are separated. Always sits at the bottom of a page, never in the navigation. Not currently used anywhere on the site (the homepage was the only page that used it, before it was simplified to show the magazine itself instead, see §5's Homepage entry); kept here as a reusable pattern.

**Plaque and progress**
Museum wall label, bottom left, always in the same position. Used on the On View page only. The blue progress bar at the foot of the screen fills over twenty seconds and is the only clock on the site.

**Field**
Square corners, hairline border (`--line`), blue on focus. Labels sit above the field in eyebrow style. No placeholder-only fields, no required-field stars.

## 5. Architecture

**Domain:** One static domain `getinspiredsociety.com`, using paths rather than subdomains.

**Society and Circle:** Circle is discontinued. The Society page and the Log in pill are gone from the site, and `/society` answers a 301 to `/`. The redirect for `society.getinspiredsociety.com` is set up in Cloudflare, not in this repo.

**Round winner.** Every submission is reviewed by an admin before it is public, and approved work stays on view for seven days. In an open call round the most viewed work wins a t-shirt. Views are deduplicated per visitor per work within 24 hours, and the raw count is never shown publicly. Tiebreak on equal views: earliest submission. The /on-view statement is "Reviewed first. Then seen.", because review decides what is public and the audience only decides the prize. The earlier plan, members voting inside Circle with André picking the lead, is dropped. This mechanism is unchanged; only the homepage's promotion of it (described next) is gone for now.

**The On View weekly open call is closed.** `ON_VIEW_SUBMISSIONS_CLOSED` in `server.js` is a single kill-switch constant: `POST /api/submit` now returns 410 before its upload middleware even runs, and the three maker-facing mails tied to that flow (archive-expiry, round-closed, approve) are switched off, while the underlying status machinery (works/rounds tables, `/on-view`, `/work/:slug`, the admin approve/reject/archive/round logic itself) keeps working unchanged for work already on the site. `/on-view/submit` 301s to `/submit` (the current Wonder open call page, registered before `express.static` like the `/society` and `/on-view/leaderboard` redirects); `public/on-view/submit/index.html` is kept on disk, permanently unreachable, only because `build/check-analytics-drift.js` and `test/main-landmark-fonts.test.js` still reference that path. About and Contact no longer mention On View or fixed artist counts ("Four times a year an issue goes out.", "There are only so many places in an issue.", the "Five / Artists an issue" stat and the "See what's on view" exit block are gone from About; Contact's routing line now reads "Work goes through the open call, not through here."). The contact form itself already worked server-side (`express.json()` + a `fetch()` POST, not a native form submit) but now also carries `name`/`action`/`method` attributes for progressive enhancement and no-JS fallback; `test/contact-form.test.js` covers the live path end-to-end against a mocked Resend fixture. **Admin: On View data export & wipe** (`GET /api/admin/on-view/export`, `POST /api/admin/on-view/wipe`, both `requireAdmin`): export returns every On View table (`works`, `tokens`, `work_views`, `rounds`) as JSON for André's own archive and downloads as a file from the admin UI's new "Data" tab; wipe (blank `works.email`, delete all `tokens` and `work_views` rows — titles, artist names, images and portfolio links are kept so `/work/:slug` keeps working) only runs after an export in the same admin session (tracked server-side, 30-minute window) and the literal confirmation text "DELETE", both in the UI prompt and the request body. `test/on-view-data-wipe.test.js` covers export contents, the two refusal paths, the wipe itself, and that `/work/:slug` still resolves afterward. Fonts are self-hosted (see §2) and the Privacy page (`build/pages/privacy.html`) was rewritten with a short, verified "what we keep, and what we don't" text; the one unresolved residual risk is `/contact`'s hCaptcha widget (`js.hcaptcha.com`), a third-party script whose own documentation says it may set cookies for bot detection — this could not be verified live in this environment (outbound network to hcaptcha.com is blocked here), so the Privacy page's "No cookies" claim is published as given but worth a manual check in a real browser.

**Homepage (`/`): the magazine itself, the statement, and a look into the gallery.** GIS World, the eventual permanent home, is still in development. The earlier hero/issue-strip/corridor/doors showcase (a temporary design while `/` had to carry the On View weekly-rotation promotion, described in older git history) is retired: André simplified the homepage once that promotion was no longer needed, to show the magazine directly instead of a separate showcase of it. Top to bottom:
1. **The magazine block**: the current issue + the archive, exactly as shown on `/magazine`, from the same source (`build/partials/magazine-block.html`, injected into both pages by `build/build.js`'s `injectMagazineBlock()`). `test/homepage-magazine-block.test.js` proves the two pages' rendered HTML for this block is byte-identical. The block's own `<h1>` (the current issue's title) is the page's only `<h1>` and its first heading.
2. **Statement**: "No algorithm decides what's here." (the page's one blue field, unchanged).
3. **Gallery end-image**: a static, full-bleed section (`min-height:100svh` on desktop, no pin, no 3D) showing `room-bloom` (the real Bloom room in the gis-gallery virtual gallery, existing responsive AVIF/WebP/JPEG variants, `object-fit:cover;object-position:center 45%`, alt "The Bloom room in the Get Inspired Society gallery"), lazy-loaded since it's below the fold, with the same copy and button the old corridor's door end-state carried: "Exhibition no. 4" / "Walk through Bloom." / "The fourth issue, hung in a room you can move through." / an outlined pill "Enter the room →" to `/gallery`. A plain `.rv` reveal on scroll-into-view (via `motion.js`), nothing scroll-pinned.
4. **Footer**: unchanged (tagline "Seventeen years of looking.").

**`ISSUE_CALL_URL` and `ISSUE_CALL_CARD_LINE`** live together in `build/pages.config.js` and are injected into the shared magazine-block (used by both `/magazine` and the homepage) by `build/build.js`, never hardcoded on either page. Since the open call Wonder opened on 9 November 2026, `ISSUE_CALL_URL` is `/submit` (the Wonder open call page, `build/pages/submit.html`, see §5a "`/submit`: the Wonder open call page" below) and the copy line is "Free to enter. Deadline 6 December 2026." The two values are swapped together, in this one file, the moment a future open call replaces this one, no separate code change needed. `ISSUE_CALL_DOOR_LINE` (the "To be seen" door's own copy) no longer exists: it was removed along with the doors section it alone fed.

**Removed along with the old homepage, and cleaned up:** the hero's two studio photos (`public/assets/hero/bloom-hero-desktop.png`/`-mobile.png`) and their responsive variants, the corridor's five per-artist crops (`corridor-room-0N-*`) and their shared data source `build/corridor-artists.js`, the GSAP/ScrollTrigger/Lenis vendor scripts and their `npm` dependencies (nothing on the site pins or 3D-transforms anything any more), and the tests that only covered those components (`test/homepage-strip.test.js`, `test/homepage-corridor.test.js`, `test/corridor-gallery-consistency.test.js`). `room-bloom` itself, the issue covers, and the Bloom spreads are untouched (still used elsewhere: `/gallery`, `/submit`'s `og:image`, the readers).

**Two footer logos, both as small, cropped derivatives.** André supplied two brush logos in the same style: Get Inspired Society (`public/assets/logos/society-logo.webp`) and Get Inspired Magazine (`public/assets/logos/magazine-logo.png`), each saved unchanged exactly as supplied (2000×2000px, a wide transparent margin around the lettering, ~250KB/~430KB). The two 1x WebP files together are about 25KB (well under a 40KB budget), the 240px pair about 35KB; `test/footer-logos.test.js` checks both the sizes and the budget. Alt text: "Get Inspired Society" and "Get Inspired Magazine". The `.footer-logos` markup is unconditional in the partial, so it shows on every page that includes the shared footer, tagline or not; the four magazine readers carry the same `<picture>` markup by hand, guarded by `build/check-footer-drift.js` (`npm run check:footer-drift`, also run by `npm run build`).

Lighthouse mobile: performance 99, accessibility 100, CLS 0.001.

### `<main>` landmark and non-blocking fonts, sitewide
Every page on the site (the 8 build-system pages, the 4 issue pages, the 4 magazine readers, `/on-view`, `/on-view/submit` and `/work/:slug`, covered by `test/main-landmark-fonts.test.js`) has exactly one `<main id="main">` landmark wrapping its primary content between the nav and the footer, and loads Archivo self-hosted and non-blocking: `<link rel="preload" as="font" type="font/woff2" href="/assets/fonts/Archivo-Variable.woff2" crossorigin>` plus an `@font-face` with `font-display: swap` pointing at that same file (see §2 — this replaced the old Google Fonts preload/swap/noscript trick sitewide). `/admin` and `/embed` (no nav, no `<main>` landmark, not covered by that test) got the same self-hosted-font swap by hand, same reasoning as every other page: no page on the site loads anything from Google's domain any more. A "Skip to content" link (`.skip-link`, visually off-screen at `top:-60px` until it receives focus, then `top:12px`) jumps to `#main` on every page that has a nav to skip past; it lives in `build/partials/nav.html` (so every build-system and issue page gets it automatically) and is hand-copied, byte-for-byte, into the pages that carry their own copy of the nav (`public/on-view/index.html`, `public/work/index.html`, every magazine reader). `public/on-view/submit/index.html` has no nav and no skip-link (nothing to skip past), only the `<main>` wrap and the non-blocking font. None of this changes any page's layout or CSS: `<main>` is a plain block element under the existing `*{margin:0;padding:0}` reset, and the skip-link is `position:fixed` and off-screen, so neither affects document flow. `test/main-landmark-fonts.test.js` (`npm run test:main-landmark-fonts`) checks every built/hand-maintained page for exactly one `<main>` and the non-blocking font pattern. `build/pages/magazine.html`'s archive-row headings were bumped from `<h3>` to `<h2>` (and the matching `.row h3`→`.row h2` CSS selector) as part of the same pass: `<h1>Bloom</h1>` (the current issue) followed directly by `<h3>` for the four archive rows skipped a level, which Lighthouse's `heading-order` audit flags; `<h2>` is the correct next level and changes nothing visually (the CSS targets the tag either way). Lighthouse mobile accessibility is 100 on `/`, `/magazine`, `/magazine/bloom`, `/gallery`, `/submit`, `/about` and `/contact`.

Nothing on the homepage links to `/submit` or `/on-view` any more; both routes still work; they're just not promoted from `/` while this showcase is live. Cross-document View Transitions (`@view-transition { navigation: auto; }`) are opted into on the homepage for internal navigation, falling back to the block wipe where the browser doesn't support it (or under reduced motion), see §6.

### 5b. Issue pages (`/magazine/<slug>`)

A build-system page since 10 November 2026 (`build/pages/issue.html`, one template fanning out to four outputs via `build/build.js`, data from `build/data/issues.js`), replacing the reader at that exact path — the reader itself is unchanged and unmoved in function, only relocated to `/magazine/<slug>/read` (see CLAUDE.md's "Issue-pagina's" and "Magazine-readers" entries). (exactly one per page, same markup/class and the reused text from `build/pages/magazine.html`'s own archive). **The archive** — the other three issues as **Archive rows** (§4): the whole row fills blue on hover, cover lifts and scales, each row's cover also carries that issue's own `view-transition-name` so a further navigation morphs too. **Footer**. **Spread addressing, new in this task:** before this, no reader supported opening at a specific spread via the URL at all — always the cover. A `?spread=N` query on the reader itself now jumps straight to that view, additive and identical in every reader (outside the issue markers). A `/magazine/<slug>?spread=N` link (the convention a spread-carrying old link now uses) is 301-redirected server-side to `/magazine/<slug>/read?spread=N` (`server.js`, same block as the `/society`/`/on-view/leaderboard` redirects, before `express.static`); a bare `/magazine/<slug>` falls through to the new issue page. A hash-only link (`#spread-N`, never visible server-side) is instead caught by a small inline script at the very top of the issue page's own `<head>`, before anything else loads, which `location.replace`s to the reader with the equivalent query string. **Not confirmed:** there is no evidence of any pre-existing spread-addressing convention anywhere (not in this repo, not in known outreach mail), so `?spread=N` is a new convention chosen for this task, not a reconstruction of one that already existed.

**Cross-document View Transition opt-in on the readers (bugfix):** each reader now carries `@view-transition { navigation: auto; }` (identical, outside the issue markers), matching the homepage and the issue pages. Without it, a navigation from an issue page (which does opt in) to the reader (which didn't) left Chromium's View Transition API in a mismatched state, logged as a console `pageerror` on every such click even though the navigation itself completed normally. No other change to any reader.

**The same crop fix, extended to the archive-row covers (bugfix):** `.i-row .cover` (the three other-issue thumbnails at the foot of every issue page) had the identical `aspect-ratio:3/4` + `object-fit:cover` bug as the hero. ## 6. Motion

A small, shared, self-hosted module, `public/js/motion.js`, plus page-specific choreography built on top of it where a page needs any (none currently do). No page loads GSAP, ScrollTrigger or Lenis any more: the homepage's former pin-driven issue strip and corridor were retired (see §5's Homepage entry), and nothing else on the site ever used them, so the vendor scripts, their `npm` dependencies and the `public/js/vendor/` copy step were all removed. `motion.js`'s own Lenis wiring is still conditional on those globals being present and simply no-ops without them. Every motion effect below is off under `prefers-reduced-motion: reduce`, falling back to the instant end state or a short fade (the sitewide `*{animation-duration:.01ms!important;transition-duration:.01ms!important}` rule, already in use elsewhere), never a larger movement.

| Effect | Where | Timing | Trigger | Reduced motion |
|---|---|---|---|---|
| Reveal | Any `.rv` element (statement rise included, via `.claim`'s own CSS) | Fade + 22px lift, 900ms; statement rise is a 105%→0 translateY over 1100ms in a clipped container | Once, at 20% in view; `data-reveal-group` staggers members 110ms apart in document order | Short fade only |
| Cursor label | Any `[data-cursor]` element | 88px circle, position lerped toward the pointer at a 0.18 factor per frame; label opacity/scale 250ms | Pointer `pointerover`/`pointerout` on a `[data-cursor]` element | Not created at all (and never on `pointer: coarse`) |
